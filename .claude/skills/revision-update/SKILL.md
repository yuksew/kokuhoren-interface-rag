# 改定の資料の確認と取り込み

正本の手順は `docs/revision_runbook.md`。最初にそれを読み、その順に進める。このスキルは、Claude が実行するときの決まりごとをまとめたもの。

## 守ること

- **入れるのは一次資料だけ**（厚生労働省・WAM NET・こども家庭庁）。審議会の資料・報道・業界の解説・民間の整理版は入れない。報道で知ったことは、一次資料で確かめるまで事実として扱わない。
- **施行日（manifest の `effective`）を推測で入れない。** 告示・事務連絡など一次資料で確かめられるまで `null`。
- **今の版は消さない。** 次の版は別の id（`{分野}_{編}_r{年}{月}`）で足し、施行日で切り替える。案は `status: draft`。確定版を取り込んだら、案は `status: superseded`。
- **費用がかかる作業は、見積もりを出して利用者に確かめてから。** 画像からの書き起こし（`batch.py submit`）と回答の評価（`eval_answers.py`、約 $1）。`batch.py plan` の見積もりを見せる。検索の評価・テキストレイヤからの組み立て・`watch.py` は無料。
- API キーは環境変数 `ANTHROPIC_API_KEY`（`.env`）。表示しない。シェルでは `set -a && . ./.env && set +a`。
- コミットと push は段階ごとに（登録・取得 → 取り込み → 評価）。

## 進め方

### 1. 新着の確認

```sh
PYTHONIOENCODING=utf-8 uv run python src/watch.py
```

- 終了コード 10 なら新着あり（`reports/watch/{日付}.md`）。0 なら新着なしで、そう伝えて終わる。
- 「リンクが 1 つも無い」と出たページは、作りが変わっている。`sources/watch.yaml` の `include` を直す。
- 令和9年度の改定ページ（介護報酬・障害の報酬改定・こども家庭庁）ができていたら、`sources/watch.yaml` に足す。

### 2. 判定

手順書の「2. 判定」の表で、新着ごとに「取り込む・案として取り込む・取り込まない」を決める。PDF を開いて確かめること:
- 案か確定版か（介護は「（確定版）」、障害は事務連絡の「【確定版】」）。
- どの編が変わったか（介護の確定版ページの「（変更なし）」、障害の施行分ページに載っている編）。変わっていない編は新しい版を作らない（リンク先のファイルの sha256 が前の版と同じ）。
- 仕様書の全文か、変更点資料・新旧対照表だけか。

判定の結果を表にして利用者に見せ、取り込む範囲を確かめてから 3 に進む。

### 3〜4. 登録・取り込み

手順書の「3. 登録」「4. 取り込み」のとおり。注意すること:
- 本文だけの資料（事務連絡・変更点資料）は `build_db.py` の `PROSE_ONLY` に足す。
- 表のある編は `config/prodN.yaml`（N は次の番号）で書き起こす。表の判定から漏れる表がないか、罫線の表を洗い出す。
- 確認キューは、PDF に文字があればテキストレイヤの同じ番号の行と照らして機械的に判定し、残りだけ原本の画像で見る。
- 作り直しの順: `build_db.py` → `build_rules.py` → `build_examples.py` → `build_daysettings.py` → `build_index.py`（`--group rag`）。

### 5. 評価

```sh
PYTHONIOENCODING=utf-8 uv run --group rag python src/eval_retrieval.py
git diff -U0 reports/retrieval_eval.md | grep "^[-+]|"
```

- 前からある質問で順位が下がったものがあれば、原因を調べて報告する（黙って評価の質問を変えない）。
- 新しい版の質問を `eval/questions.yaml` に足す: 次の版を聞く質問（`kind: next`）と、同じ項目を今の版で聞く質問（次の版が今の版として答えられないことの確認）。本文が正解なら `gold: [{doc: <id>, kind: prose}]`。
- 実際の質問で答えを 1〜2 問確かめる（`src/ask.py "<質問>" --domain kaigo`。1 問 約 $0.02）。次の版の抜粋に【施行前の次の版】が付き、今の版と分けて答えているか。

### 6. 施行日の確定・切り替え

手順書の「6.」のとおり。施行日が一次資料で確かめられたら `effective` を入れる。施行日を過ぎたら、評価の基準日（`eval_retrieval.py`・`eval_answers.py` の `AS_OF`）を更新する。

### 7. 記録と報告

- `sources/README.md`（最新と判断した根拠）、`uv run python src/list_sources.py`（出典一覧）、README の件数、手順書の「令和9年度改定の見込み」の表を更新する。
- 利用者への報告: 何が出ていたか（一次資料のリンク）、何を取り込んだか・取り込まなかったか、評価の変化（下がった問は正直に）、かかった費用、次に何が出そうか。
